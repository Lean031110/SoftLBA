- Decisiones importantes:
  - Sistema de permisos nuevo coexiste con el viejo: `permissions-v2.ts` se importa solo desde los endpoints nuevos y modificados; el código existente sigue usando `permissions/index.ts` sin tocar. La migración puede ser incremental.
  - ADMIN hereda automáticamente cualquier nuevo permiso añadido a `PERMISSIONS` vía `Object.values(PERMISSIONS)` — no requiere actualizar la matriz.
  - WorkShift.areaId es opcional (null = turno genérico, sin área específica); esto permite cajeros sin área asignada.
  - Order.parentOrderId usa onDelete: SetNull para no perder el child si el parent se borra (aunque en práctica el parent casi nunca se borra — los pedidos se archivan, no se eliminan).
  - FinanceEntry.annulCompensationEntryId es @unique para forzar relación 1-a-1 (una entrada es compensada por a lo sumo otra entrada). Esto evita crear múltiples compensaciones de la misma entrada.
  - La anulación financiera NO toca la entrada original en términos de monto; solo cambia su `status` a ANNULLED. El efecto neto en los totales se logra con la entrada compensatoria. Esto preserva el histórico auditable: la entrada original sigue visible con su monto original, marcada como anulada.
  - Split de cuenta: el pedido hijo hereda el status del padre (ej: si el padre está ENVIADO, el hijo también nace ENVIADO) para no romper el flujo de cocina. Los items del hijo preservan el status individual del item original (PENDIENTE, EN_PREPARACION, LISTO, etc.) para no obligar a la cocina a re-preparar lo que ya estaba listo.
  - Transfer-table valida que la mesa destino esté en la misma área que el pedido (si la mesa tiene areaId asignado). Mesas "globales" (areaId=null) pueden recibir pedidos de cualquier área.
  - El checksum se calcula con `crypto.createHash('sha256')` sobre el buffer completo del archivo. Para SQLite (< 100MB típicamente) esto es O(1) en memoria y suficientemente rápido (< 50ms en mis tests).
  - Backward compat en restore: si el registro de Backup tiene `checksum=null` (backups pre-FIX-23-25), la restauración procede pero loguea advertencia. Esto evita romper restauraciones de backups antiguos.
  - El auto-backup pre-restore ahora también guarda su checksum, para que pueda verificarse al restaurarlo si fuera necesario.
