# Task v0.17-export-sync — Resumen del subagente

## Tarea
Crear 2 endpoints de exportación (PDF/Excel para orders/finances/inventory) y 1 endpoint idempotente de sincronización de inventario con receta.

## Archivos creados

### 1. `src/app/api/admin/export/route.ts`
**GET /api/admin/export?type=pdf|excel&data=orders|finances|inventory&from=YYYY-MM-DD&to=YYYY-MM-DD**

- Auth: solo ADMIN (`getCurrentUser()` + check `role === 'ADMIN'`).
- Validación de params con regex `^\d{4}-\d{2}-\d{2}$` para `from` y `to`.
- Tres datasets:
  - **orders**: pedidos con número, fecha, mesero, área, mesa, items (joined como `"2× Pizza, 1× Refresco"`), total, estado y método de pago (combinado de `payments` o fallback a `paymentStatus`).
  - **finances**: entradas financieras con fecha, tipo, categoría, descripción, monto, moneda, referencia y usuario.
  - **inventory**: productos activos con stock general, reservado, costo, precio, minStock y **una columna por área** (dinámica según áreas activas).
- **Excel (exceljs)**:
  - Fila 1: título del reporte + nombre del restaurante.
  - Fila 2: rango de fechas en cursiva.
  - Fila 4: headers en negrita, fondo indigo (`4F46E5`), texto blanco, bordes.
  - Filas de datos con bordes suaves y fondo alterno implícito por bordes.
  - Auto-ancho calculado a partir del header + contenido (min 12, max 60).
  - Vista congelada en la fila de headers.
  - Devuelve `Buffer` con Content-Type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
- **PDF (jspdf)**:
  - Orientación landscape, A4.
  - Header centrado con nombre del restaurante (16pt bold), subtítulo "Reporte de {data}" (11pt), rango (9pt italic).
  - Tabla con headers en fondo indigo + texto blanco, filas con fondo alterno, bordes finos.
  - Truncado de celda con ellipsis si excede el ancho proporcional.
  - Salto de página automático con repetición de header.
  - Footer con total de registros y timestamp.
  - Anchos de columna proporcionales al `width` definido en cada `ColumnDef`.
  - Devuelve `Buffer` con Content-Type `application/pdf`.
- Headers HTTP:
  - `Content-Type` correcto por formato.
  - `Content-Disposition: attachment; filename="{data}-{YYYY-MM-DD}.{ext}"`.
  - `Content-Length` y `Cache-Control: no-store`.
- 404 si no hay registros para exportar.

### 2. `src/app/api/admin/inventario/sync-recipe/route.ts`
**POST /api/admin/inventario/sync-recipe** (body: `{ orderId, itemId }`)

- Auth: solo ADMIN.
- Validación con Zod (`orderId` y `itemId` strings no vacíos).
- Recibe el `orderId` + `itemId` (el item que se marcó como LISTO en cocina).
- **Idempotencia**: usa `reference = "recipe-sync:{orderId}:{itemId}"` en `StockMovement`. Antes de procesar, busca si ya existe un movimiento con esa referencia. Si existe → retorna `{ alreadySynced: true, syncedAt }` sin volver a descontar.
- Busca la receta del producto del item (`db.recipe.findUnique({ where: { productId } })`).
- **Si el producto no tiene receta**: crea un StockMovement "marcador" con `quantity=0` para que la idempotencia funcione igual y registra audit `SYNC_RECIPE_NO_RECIPE`.
- **Cálculo de escala**: `scale = orderItem.quantity / recipe.yield`. Cada ingrediente se descuenta `ingredient.quantity * scale` (redondeado a 4 decimales).
- **Por cada ingrediente** (en transacción Prisma):
  1. Determina área: `ingredient.product.areaId` → `orderItem.targetAreaId` → `order.areaId`.
  2. Busca `AreaInventory` para (área, ingredient.productId).
  3. Si existe: decrementa `quantityNeeded` (puede quedar negativo). Si `stockBefore < quantityNeeded` → marca `insufficient=true` y arma mensaje de alerta.
  4. Si no existe AreaInventory: intenta fallback al `InventoryItem` general (con alerta de "no hay stock en área").
  5. Si tampoco hay InventoryItem: registra alerta "no tiene inventario registrado" pero no bloquea.
  6. Crea `StockMovement` con `type=SALIDA`, `productId`, `areaId`, `quantity=quantityNeeded`, `unit`, `reason="Consumo por pedido #{order.number} (item XXXXXX)"`, `reference=referenceKey`.
- **Audit log**:
  - Acción `SYNC_RECIPE` con `result="SUCCESS"` o `"ALERT"` según si hubo alertas.
  - `after` con detalle completo: número de pedido, producto, recipeId, yield, itemQty, scale, deductionsCount, alertsCount y array `deductions` con producto/área/qty/source/before/after/insufficient por cada ingrediente.
  - Por cada alerta, un audit log adicional con `action="STOCK_ALERT"`, `entity="inventory"`, `result="ALERT"` y el mensaje descriptivo.
- Respuesta: `{ ok, synced, orderNumber, itemId, productName, deductionsCount, alertsCount, alerts[], deductions[] }`.

## Decisiones técnicas

1. **Idempotencia por `reference` field**: SQLite permite consultas exactas por `reference`, mucho más simple y robusto que mantener una tabla aparte de "items sincronizados". El formato `recipe-sync:{orderId}:{itemId}` es único y consultable.
2. **Decremento con stock negativo permitido**: la spec dice "no bloquea" → descuento siempre; si el stock queda negativo, la alerta lo documenta y el admin ve el faltante. Esto mantiene la consistencia entre `StockMovement.quantity` y la suma del descuento real.
3. **Fallback al inventario general**: si un ingrediente no tiene `AreaInventory` en el área esperada pero sí `InventoryItem`, se descuenta del general y se registra alerta. Esto evita que la falta de un traslado previo bloquee la sincronización.
4. **Excel con cabecera de reporte + rango**: en lugar de empezar directo con la tabla, se agregaron 2 filas merged con el título del restaurante y el rango de fechas para mayor legibilidad al imprimir/abrir.
5. **PDF con autoTable manual**: como `jspdf-autotable` no está instalado, se implementó una tabla manual con `setFillColor`, `rect`, `text`, cálculo proporcional de anchos y salto de página. Funcionalidad equivalente.
6. **`export const dynamic = 'force-dynamic'`** en el route de export porque usa cookies para autenticación y nunca debe ser cacheado/estático.
7. **Tipado estricto** con `ColumnDef` y `DataType`/`ExportType` para evitar errores en runtime.
8. **Sin instalación de nuevos paquetes**: `exceljs` y `jspdf` ya estaban en `package.json`.
